**Profile hold (D6)**
- `ProfileViewModel.withdrawingConsent` drives `.disabled` on the Demo data toggle and the Log out pill. The reason
  `withdrawalHoldReason` is the Demo row's detail (part of the toggle's label), a caption under the buttons row
  (`accessibilityHidden`) and Log out's hint. Footer while withdrawing: "Withdrawing your consent. Syncing stops once RYFT
  confirms." (taken from design §4; the lead's ticket listed only the reason and the announcement).
- The announcement goes through the `announce` closure on the VM (`@ObservationIgnored`). Tests swap in a recorder,
  so there is no global state.
- The lead chose the draft's look: `RyftToggleStyle(dimsLabel: false)` dims the track alone. It defaults to true, so every
  other disabled toggle keeps the whole-row dim. Profile passes `dimsLabel: !held` on the Demo row only (commit 96ddfe4).
  `RyftToggleDimTests` pins both looks.
  Ink on surface: textPrimary 0.95 (0.38 dimmed); textTertiary detail and off track 0.49 (0.22 dimmed).
  To find a label's title: box of pixels > 0.75. The detail is what lies below that box.
- Mutant pitfall: "Demo row back to `RyftToggleStyle()`" and "default flipped to false" cancel each other, so never group
  them together.
- Row details in GroupedRowText are `textTertiary`. The lead wrote "the reason stays textSecondary" (that is the Log out
  caption's colour in the design). I kept textTertiary and flagged it.
- Seams: `MockPlatformAPI.beforeRevokeConsent` runs before `enter("revokeConsent")`, so a held request can still fail
  via `faults`. "Ended unsent" = `onboarding.switchAccount(knownAccount)` first, hold an invite with `beforeInvite`
  so the withdrawal waits its turn, then log in as account B and call `switchAccount`.
- `ProfileShotGraph.releaseWithdrawal()` opens the gate before `tearDown`, otherwise a hosted test hangs.

**Hosted probe lessons**
- A window taller than ~2,700 pt draws black (texture limit). Use 2,600 pt and scroll the page's scroll view to bring
  a control on screen before `WindowPixels`.
- After scrolling back to the top, `settle()` BEFORE reading accessibility frames, or the frames are still the
  scrolled ones (the render came out at the wrong place).
- A clean render of one region: give `UIGraphicsImageRenderer` bounds of `y: pill.minY - k`; `y: 0` gives the
  window's top whatever the scroll.
- Pixel bands under a control: a fixed 30 pt band reached the next group's header (Developer, 18 pt under the row), so
  the "caption dropped" mutant SURVIVED. Fix: end the band 1 pt above the next AX node below the control
  (`w.nodes().map(\.frame.minY).filter { $0 > pill.maxY }.min()`). This works because the caption is hidden from AX.
- Grouped mutants: a test's `wait("held") { logOut disabled }` masked every other Profile mutant grouped with
  "Log out not held". Give a mutant that breaks a shared wait condition a group of its own.

**Train failure words**
- `TrainReadFailure.text(offline:heldBack:whenOffline:whenFailed:)`: held back gives `RefreshIssue.Reason.busy`,
  offline gives the old "when you're online" key, and a failure online gives the page's own "couldn't be loaded. Try again."
- Each page has `offlineFailureText`, `onlineFailureText` and `failureText(offline:heldBack:)`.
- `SessionDetailViewModel` keeps `offline`, and `SessionDetailPage` takes `failureText`, not `heldBack`.
- `Fetched.offline` is true only for `.declined(.offline)` or a lost connection (not a timeout, HTTP error or `.over`).
  For pipeline tests use a 404: transient errors retry on `clock.sleep`, which hangs on a `TestClock`.

**Strings**
- `sync-strings.py` writes new keys as `{}` with no comment, but recent commits carry the source comments. Write them
  in by script (exact text replacement, JSON-escaped). A key whose source comment changed should drop
  `isCommentAutoGenerated`.
- To split one catalog across commits: build the intermediate file by script, `git add`, commit, then restore the full
  file.

**Running**
- A blocking `until` loop moves to the background after 180 s, so put long runs in `run_in_background` from the start.
- Mutation runs restore with `git checkout -- <files>`, which reads the index, so commit first.

**Security and code review fixes (S-1, S-2, N-1 to N-4, nits 3 to 5)**
- Guard in the model, not only the view: `logOut`, `setDemoMode`, `endDemo` return early while `withdrawingConsent`;
  `sendFirstThenLogOut` returns `.held` before and after its 10 s wait. Model tests on a `TestClock` graph
  (`WithdrawalHoldModelTests`), with `RequestHold` on `activitySource.beforeWrite` and `Gate` on `beforeRevokeConsent`.
- Fail fast for a write the user waits on: `SettingsWrite.answer(in:)` (single attempt on the fail-fast session, 25 s
  deadline on `env.clock`) plus an `isOnline` guard first. Map `NoAnswer` to `APIError.transport(.timedOut)` so the
  coordinator's `fallbackMessage` keeps its "No connection" sentence: no new string.
- Once a request has a deadline on `env.clock`, a hosted test holding it on `SystemClock` can see it end mid-render.
  Use `TestClock(now: .now)`; previews already do (`SleepPlannerView`, `TodayView`). `ProfileShotGraph.make(_:clock:)`.
- To end a hold "when recorded" without a second-withdrawal race, read the record (`withdrawingConsent =
  isWithdrawing && state.user?.consent != nil`) instead of clearing the coordinator's flag early. The announcement moves
  with it through `withdrawConsent(onRecorded:)`. Hold the re-check with the DEBUG `beforeMeRead` hook.
- `HostedWindow.nodes()` lists only SwiftUI `AccessibilityNode`s that have a label. A SwiftUI `TextField` is a UIKit
  `UITextField`: walk the subviews for its `accessibilityIdentifier` and read `isEnabled`.
- `-only-testing:RyftTests/X` takes a Swift Testing suite's struct name, not a file's (`ViewModelTests.swift` holds
  17 suites). In zsh, a `$args` string is passed as one word: build the list with `set -- "$@" …`.
- Hosted `ProfileDataTests` (`hostedTap` settle at 32 s, `hostedIdentifiers` at its 60 s limit) fail when the shared
  Mac's load climbs past about 600 during a run, even though the gate passed under 200. Rerun them on their own and report it.
- Making a SwiftUI page's parameter required (`SessionDetailPage.failureText`) turns the "page ignores the model's
  sentence" mutant into a compile error.

**Round 3 (A to D)**
- A write that may have reached RYFT unanswered: classify with `SettingsWriteFailure(error) == .noAnswer` (excluding
  `isCancellation`), not by catching `SettingsWrite.NoAnswer` alone. The fail-fast session's own 20 s request timeout
  fires before SettingsWrite's 25 s deadline and arrives as `transport(.timedOut)`. Keep "No connection" for the
  offline pre-flight only.
- A re-read (`check(force:changedSince:)`) that finds the consent gone raises the consent sheet unless `.consent` is
  deferred before the read. Insert it first and remove it again if the consent is still there.
- In the test environment `settings.demoMode` falls back to `demoDefault`, which is on, and `ProfileViewModel.demoMode`
  reads the pinned `env.isDemo`. A test of "the switch didn't move" sets the setting off and reads it.
- A mutant that removes a local's only use fails the strict build (rc 65), and the tests then run on the old products
  and "pass". Read `xcodebuild rc=` before the results, and replace the use with `_ = x`.
- After UISmoke on a reused simulator, test-without-building can hang ("test runner hung before establishing
  connection"; `scripts/ci-simulator.sh` documents the same in CI). Erase the device, or make a fresh one:
  `CI_SIM_NAME="RYFT f2" sh scripts/ci-simulator.sh`. Run mutants before UISmoke.
